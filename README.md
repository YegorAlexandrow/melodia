# Фонотека — каталог винила «Мелодия»

Персональный (однопользовательский, self-hosted) сервис для каталогизации домашней
коллекции виниловых пластинок с акцентом на фирму «Мелодия». Метаданные тянутся из
Discogs (слой `Master`/`Release`), а всё личное — экземпляр, сохранность по Goldmine,
две независимые оценки (музыка / звук пресса), заметки, аудио-оцифровки (needledrop)
и журнал прослушиваний — живёт отдельным слоем и не теряется. Всё датировано.

## Возможности (MVP)

- **Добавление через Discogs** — поиск по каталожному номеру (с нормализацией),
  карточки-кандидаты, предпросмотр треклиста, создание экземпляра(ов) — включая
  «несколько прессов» одного издания.
- **Коллекция** — сетка обложек или плотный список, фильтры (жанр, статус, завод,
  тег), полнотекстовый поиск, индикаторы аудио/заметок.
- **Карточка экземпляра** — обложка, статус, избранное, две оценки с историей,
  треклист по сторонам (раскрытие трека → быстрое добавление аудио), пресс и
  сохранность (Goldmine раздельно пластинка/конверт, завод из справочника, матрица,
  ГОСТ), покупка и место хранения.
- **Заметки** (markdown) — к экземпляру/треку, закрепление; сквозная лента по дате.
- **Аудио** — привязка своих оцифровок (локальное хранилище) и внешних референсов;
  воспроизведение через ссылку/скачивание; mutagen-автозаполнение тех-полей.
- **Журнал прослушиваний** и **статистика** (по заводам, жанрам, «давно не слушал»).
- Светлая/тёмная тема, дизайн направления «Конверт».

## Стек

- **Бэкенд:** Python · FastAPI · MongoDB · Beanie (нативный async-драйвер PyMongo).
- **Фронтенд:** React · Vite · TypeScript.
- **Дизайн:** точные токены и шрифты в `frontend/src/styles/tokens.css`.

## Структура

```
melodia/
├── backend/    — FastAPI + MongoDB + Beanie (API, сервисный слой, модель данных)
├── frontend/   — React + Vite + TS (экраны A–F, дизайн-токены, темы)
├── design/     — справочные материалы: бриф, модель, дизайн-хэндофф
├── scripts/    — backup.sh (бэкап БД+медиа), session-setup.sh (установка зависимостей)
└── docker-compose.yml — локальный MongoDB
```

## Быстрый старт

### Вариант A — всё в Docker (с хот-релоадом)

```bash
docker compose up            # mongo + backend + frontend
# фронтенд: http://localhost:5173   бэкенд: http://localhost:8000/docs
```

Код прокидывается бинд-маунтами (`./backend`, `./frontend`), правки подхватываются
на лету: бэкенд — `uvicorn --reload`, фронтенд — Vite dev-server (HMR). Зависимости
(`.venv`, `node_modules`) живут внутри контейнеров и не конфликтуют с хостом.
После изменения зависимостей: `docker compose up --build`.

### Вариант B — локально

```bash
# 1. MongoDB
docker compose up -d mongo

# 2. Бэкенд
cd backend
cp .env.example .env            # при необходимости поправить настройки
uv sync                         # или: python -m venv .venv && . .venv/bin/activate && pip install -e ".[dev]"
uvicorn app.main:app --reload   # http://localhost:8000  (Swagger: /docs)
# проверка: curl localhost:8000/api/health -> {"status":"ok","plants":8}

# 3. Фронтенд (в новом терминале)
cd frontend
npm install
npm run dev                     # http://localhost:5173 (прокси /api → :8000)
```

Либо одной командой поставить все зависимости: `bash scripts/session-setup.sh`.

## Discogs

Интеграция работает **анонимно** (лимит ~25/мин). Для повышенного лимита и обложек
укажите персональный токен в `backend/.env` (`DISCOGS_TOKEN`). Уникальный
`DISCOGS_USER_AGENT` отправляется всегда; на 429 клиент делает backoff и повтор.

## Медиа

Обложки и аудио хранятся локально в `MEDIA_DIR` (по умолчанию `backend/media/`),
в БД — только локаторы; отдача файлов через `/api/media/...`.

## Тесты и линт

```bash
cd backend && . .venv/bin/activate
pytest            # юнит-тесты (нормализация кат.№, маппинг Discogs, клиент)
ruff check app    # линт
cd ../frontend && npm run build   # типы (tsc) + сборка
```

## Бэкап

```bash
MONGO_URL=mongodb://localhost:27017 DB_NAME=vinyl MEDIA_DIR=./backend/media \
  scripts/backup.sh ./backups
```
